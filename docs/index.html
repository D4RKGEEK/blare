Your error channel, unmuted.

blare catches every crash in your Python and Node services, groups the identical ones into a single message, and posts it to Slack, Discord or Teams. No server, no database, no dashboard — a library and one environment variable.

One URL decides the format

Paste the webhook URL your chat tool gave you. blare reads the hostname and renders the native format — there is no scheme to learn and no per-service config. Several URLs, comma separated, all get a copy.

It posts into a chat room, so it is paranoid

      
Local variables, request bodies, response bodies, query strings and environment variable values are never collected in any configuration. Everything that does leave is scrubbed. Try it: paste something that shouldn't leak.

        What the channel sees
        

      

    


    

      

        
ClassRule

        
          
Never collectedlocals, request and response bodies, query strings, environment variable values — there is no flag that turns these on

          
Pattern-scrubbedbearer tokens, JWTs, AWS access keys, GitHub and Slack tokens, PEM private keys, passwords inside connection strings, Luhn-valid card numbers

          
Key-scrubbedpassword, token, secret, authorization, cookie and two dozen more, replaced wholesale at any depth

          
Orderredaction runs after fingerprinting — changing a rule can never regroup your history — and before rendering, so no sink ever sees a raw value

        
      

    

  







  

    

      
The whole configuration surface

      
Ten environment variables. There is no config file, no init options you have to learn, and nothing to run.

    


    

      

        
VariableDefaultWhat it does

        
          
BLARE_SINKS—Webhook URLs, comma separated. The only one you must set.

          
BLARE_ENVunknownShown on every alert: production, staging, a branch name.

          
BLARE_SERVICEderivedThe service name on the alert. Defaults to the process or package name.

          
BLARE_LEVELERRORMinimum level that alerts. WARNING if you want more.

          
BLARE_DEDUPE_WINDOW300Seconds of silence per fingerprint after an alert goes out.

          
BLARE_MAX_PER_HOUR20Hard ceiling across all problems. 0 disables the ceiling.

          
BLARE_IGNORE—Glob patterns dropped before anything else runs.

          
BLARE_STATEfilememory, file, or redis://… to dedupe across hosts.

          
BLARE_DRY_RUNfalseRender to stderr and send nothing. Good for a first deploy.

          
BLARE_ENABLEDtrueThe off switch, for when you need one at 3am.

Same failure, same fingerprint, every language

      
blare is specified first and implemented per language. SPEC.md defines fingerprinting, throttling, redaction and the payload exactly, and conformance/ holds the shared JSON fixtures every port must pass — so a Node service and a Python service in one fleet group the same failure under the same hash, byte for byte.

What blare is not

      
The gaps are deliberate, and saying so up front is cheaper than disappointing you in week two.

    


    

      

        
ToolWhat it doesWhat it leaves to you

        
          
Apprise · ShoutrrrDeliver a message to 100+ servicesThey capture nothing — you write the glue

          
Sentry · GlitchTip · BugsinkCapture, store, search and display errorsA server, a database and a dashboard to run

          
express-error-slack and friendsThe glue, for one framework and one channelOne language, no grouping, mostly unmaintained

          
blareCapture, group and deliver, as a libraryNo history, no search, no UI — on purpose

        
      

    


    

      

        
No history, search or dashboard

        
It is a library. If you need to look a failure up next week, run an error tracker and let blare stay out of it — they solve different problems and work fine together.

      

      

        
No metrics, traces or uptime checks

        
Not an observability platform, and not trying to become one. It alerts operators, never your users.

      

      

        
No browser support yet

        
A webhook URL in frontend JavaScript is a public secret — anyone can read it and spam your channel. Browser capture needs a relay through your own backend, and that comes after the server-side ports.

      

      

        
Not battle-proven yet

        
v0.1.0, a few hundred tests, behaviour pinned to shared fixtures rather than to anyone's memory. It has not yet run through a real production incident — tested and battle-proven are different claims.

      

    

  







  

    

      
Frequently asked

    


    

      

        Why not just post to a Slack webhook myself?
        

          
Because posting the message is the easy half. The half that gets skipped is the throttling: when one failure fires 847 times, you get 847 messages, and the channel is muted by Friday.

          
Around that one webhook call blare adds fingerprinting, a dedupe window, an hourly ceiling, cross-process state, the right stack frame, secret redaction, and delivery on a worker thread that never raises into your request. You will write the first half in an afternoon and the second half a week later, after it bites you.

        

      

      

        How do I send Python errors to Slack?
        
pip install blare, call blare.init() once at startup, and set BLARE_SINKS to your Slack incoming-webhook URL. Every logger.error(...) call you already have, plus every unhandled exception, becomes a Slack message — grouped, so a flood arrives as one message with a count.

      

      

        How do I send Node.js or Express errors to Discord?
        
npm install @geekvb/blare, call blare.init(), and add app.use(blareErrorHandler()) after your routes. Set BLARE_SINKS to your Discord webhook URL — blare detects Discord from the hostname and renders an embed.

      

      

        Can a coding agent install it for me?
        
Yes, and that is the shortest path. llms.txt is a brief written for agents rather than people: the install command per ecosystem, where init() belongs, the eleven framework hooks and how to choose one, the environment variables, and the smoke test to finish on. Copy the prompt above into Claude Code, Cursor or Codex and it does the wiring and proves it worked.

      

      

        Is this a Sentry alternative?
        
No, and it is worth being precise. Sentry captures, stores, searches and displays errors. blare captures and notifies, then forgets. If you want to investigate a failure next week, you want Sentry, GlitchTip or Bugsink. If you want your team to find out in Slack within seconds without running any infrastructure, you want blare. Plenty of teams would reasonably run both.

      

      

        Does it need Redis or a database?
        
No. Dedupe state defaults to a single lock-guarded file in the OS temp directory, which is enough for every process on one host — four Gunicorn workers seeing one crash send one alert. Point BLARE_STATE at a Redis URL only when you run several hosts and want them to deduplicate together. (Redis is implemented in the Python port; the Node port falls back to the file and says so.)

      

      

        What happens if Slack goes down?
        
You lose alerts, never requests. Delivery happens on a worker thread behind a bounded queue, retries twice, and never raises into your application. If the queue fills, blare drops alerts and counts the drops rather than applying back-pressure to production traffic.

      

      

        Will it leak secrets into my chat channel?
        
It is built not to. Request bodies, local variables, query strings and environment variables are never collected at all. Everything that does leave is scanned for bearer tokens, JWTs, AWS keys, GitHub and Slack tokens, private keys, URL passwords and card numbers, and keys named password, token, secret and similar are replaced wholesale. There is a live demonstration above, and the rules are in SPEC.md section 6.

      

      

        Why are the Python and npm package names different?
        
npm's typosquatting filter refuses the unscoped name blare (too close to base, brace, slate) and blarejs (one character from blakejs), and the @blare scope belongs to someone else. So npm gets @geekvb/blare and PyPI keeps blare. Same project, same spec version, same conformance fixtures.

      

      

        What does it cost, and what does it send home?
        
Nothing and nothing. Apache-2.0, no account, no API key, no telemetry, no hosted component. Your alerts go from your process to your webhook URL and nowhere else.
