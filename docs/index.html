Capture, decide, deliver

Two of those are easy. The middle one is why this is a library and not a snippet.

Capture
A logging handler and a crash hook. No application code.
Decide
Fingerprint, group, throttle, cap, redact. Nearly all of the work.
Deliver
Render for the provider, post on a worker thread, retry twice.

First, it attaches to the logging calls you already wrote, and to the hook that fires when a process dies.

Then it answers the only question that matters at 3 a.m.: is this worth waking someone for, or is it the four hundredth copy of something already reported? Suppressed occurrences ride along as a count on the next alert, so nothing is lost and no background timer is needed.

Last, it posts on a worker thread behind a bounded queue, so a chat outage can never become back-pressure on production traffic.

What it captures and where it sends

Captures

Your existing log calls

Nothing to change. The call you already have becomes the alert.

logger.error("payment failed")
Unhandled crashes

Alerts, then re-raises. Swallowing a crash in order to report it would be worse than the crash.

sys.excepthook · threading.excepthook
FastAPI, Starlette, Litestar, Quart 
app.add_middleware(BlareASGIMiddleware)

Adds the method, the path and the templated route, so one broken endpoint is one alert rather than one per user id.

Flask 
from blare.integrations.flask import install
install(app)

Hooks the framework signal rather than WSGI, because Flask turns an exception into a 500 before any WSGI wrapper sees it.

Django 
from blare.integrations.django import install
install()

Call it once from your AppConfig.ready, and every view exception is covered.

Celery

A failed job produces no 500 and nobody reads a worker log. This is the silence blare exists for.

Sends to

Slack

Block Kit, with a fallback line that stands alone for notifications and screen readers.

BLARE_SINKS=https://hooks.slack.com/services/…
Discord

Embeds, with every field kept inside the 1024-character limit the API enforces.

Microsoft Teams

Teams has two incompatible webhook shapes, and sending the wrong one is accepted and then silently shows nothing. blare picks by hostname, so you never find that out during an incident.

A Power Automate workflow URL takes an Adaptive Card; an older Office 365 connector takes a MessageCard. blare sends whichever the hostname calls for.

Anything else

The generic sink posts the canonical event unchanged, so PagerDuty, n8n, a Lambda or your own relay all work today without blare knowing about them.

What it won't do

No history, no search, no dashboard

blare is a library. It tells you something broke, and then forgets. If you need to look a failure up next week, run an error tracker (Sentry, GlitchTip or Bugsink) and let blare stay out of it. Being the thin thing is the point.

No browser or React support yet

A webhook URL in frontend JavaScript is a public secret: anyone can read it and spam your channel. Browser capture needs a relay through your own backend, which is a different shape of product. It comes after the server-side ports, not before.

It will not send your request bodies

Local variables, request bodies, response bodies and environment variable values are never collected, in any configuration. What does leave is scanned for bearer tokens, JWTs, AWS keys, GitHub and Slack tokens, PEM private keys, passwords inside connection strings, and card numbers that pass a Luhn check.

It will not alert four times for one crash

Dedupe state lives in a lock-guarded file shared by every process on the host, so four Gunicorn workers seeing one failure send one message. Across several hosts, point BLARE_STATE at Redis and the whole fleet deduplicates together.

It will not break your deploy

No runtime dependencies at all, so there is no version conflict to drag in. Delivery never raises into the host, the queue is bounded, and a webhook that has started refusing connections costs you alerts, never requests.

Alert in one line

pip install blare
import blare
blare.init()

Then set BLARE_SINKS to the webhook URL your chat tool gave you. Confirm it is wired up before you need it with python -m blare --send.
