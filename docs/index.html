How it works

Capture, decide, deliver

Two of those are easy. The middle one is why this is a library and not a snippet.

1

Capture

A handler on your logger and a hook for crashes. The logger.error calls you already wrote become alerts, with no change at the call sites.

2

Decide

Fingerprint, group, throttle, cap, redact. Nearly all of the work, and the only question that matters at 3 a.m.: is this worth waking someone for, or is it the four hundredth copy of something already reported?

3

Deliver

Rendered for your provider and posted on a worker thread behind a bounded queue, so a chat outage can never become back-pressure on production traffic.

Integrations

Works with what you already run

Log and crash capture need no code changes at all. A framework takes one line.

Python

FastAPI, Starlette, Litestar, Quart, Flask, Django, Celery, and any WSGI app. Plus the standard logging module and unhandled exceptions.

app.add_middleware(BlareASGIMiddleware)   # FastAPI
install(app)                              # Flask
install()                                 # Django, Celery

Node.js & TypeScript

Express, Fastify, NestJS and Next.js on the server, plus pino and winston, uncaughtException and unhandledRejection.

app.use(blareErrorHandler());             // Express
app.register(blarePlugin);                // Fastify
export { onRequestError } from "@geekvb/blare/next";

Slack, Discord, Microsoft Teams

Paste the webhook URL your chat tool gave you. The provider is detected from the hostname, so there is no URL scheme to learn. Teams has two incompatible webhook shapes; blare picks the right one by host.

Anything else

The generic sink posts the canonical event as JSON, unchanged. PagerDuty, n8n, a Lambda or your own relay all work today without blare knowing about them.

{"fingerprint":"9f2a41c7b0e3d518",
 "occurrences":{"since_last_alert":847}}

Questions

Frequently asked

How do I send Python errors to Slack?

pip install blare, call blare.init() once at startup, and set BLARE_SINKS to your Slack incoming-webhook URL. Every logger.error(...) call you already have, plus every unhandled exception, becomes a Slack message — grouped, so a flood arrives as one message with a count.

How do I send Node.js or Express errors to Discord?

npm install @geekvb/blare, call blare.init(), and add app.use(blareErrorHandler()) after your routes. Set BLARE_SINKS to your Discord webhook URL; blare detects Discord from the hostname and renders an embed.

Is this a Sentry alternative?

No, and it is worth being precise. Sentry captures, stores, searches and displays errors. blare captures and notifies, then forgets. If you want to investigate a failure next week, you want Sentry, GlitchTip or Bugsink. If you want your team to find out in Slack within seconds without running any infrastructure, you want blare. Plenty of teams would reasonably run both.

Does it need Redis or a database?

No. Dedupe state defaults to a single lock-guarded file in the OS temp directory, which is enough for every process on one host. Point BLARE_STATE at a Redis URL only when you run several hosts and want them to deduplicate together.

What happens if Slack goes down?

You lose alerts, never requests. Delivery happens on a worker thread behind a bounded queue, retries twice, and never raises into your application. If the queue fills, blare drops alerts and counts the drops rather than applying back-pressure to production traffic.

Will it leak secrets into my chat channel?

It is built not to. Request bodies, local variables, query strings and environment variables are never collected at all. Everything that does leave is scanned for bearer tokens, JWTs, AWS keys, GitHub and Slack tokens, private keys, URL passwords and card numbers, and keys named password, token or secret are replaced wholesale.

Why are the Python and npm package names different?

npm's typosquatting filter refuses the unscoped name blare and the @blare scope belongs to someone else, so npm gets @geekvb/blare while PyPI keeps blare. Same project, same spec version, same conformance fixtures.
